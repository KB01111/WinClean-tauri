# WinClean 2.0 — Design (approved defaults)

Goal source: session goal `WinClean 2.0` for ASUS ROG Zephyrus G16
(Ryzen AI 9 HX 370, 32 GB, Radeon 890M, RTX 4070 8 GB, XDNA 2 NPU).
Clarifying questions timed out; recommended safe defaults apply:
UAC per privileged action, conservative EcoQoS, all slices capability-gated.

## Architecture (unchanged stack)

Tauri 2 + Rust + React/TS + shadcn/ui. New Rust feature modules under
`src-tauri/src/optimizer/` (policy, services, processes, power, hardware,
capabilities, audit). No new JS agent framework; `@openai/agents` extended.
SQLite gains `optimizer_snapshots` + `optimizer_audit` (additive migration).

## Safety contract

- Non-admin by default. Service start-type / power-plan writes go through
  SCM / PowrProf and fail with a clear elevation error when denied; the UI
  surfaces it. No Defender/Update/Search/driver service is ever mutable:
  `policy::classify_service` returns `Protected` and the command rejects.
- Every mutation: snapshot-before (JSON in SQLite) → apply → verify by
  re-read → audit row. Rollback re-applies the snapshot. Interrupted ops
  leave `pending` audit rows visible in History.
- EcoQoS: `SetProcessInformation(ProcessPowerThrottling)`. Protected:
  foreground app, VS Code/Cursor/Codex/Claude/OpenCode, compilers, games,
  AI inference. Apply requires explicit PID list; restore sets
  `ControlMask=0`. WinClean never terminates processes.
- RTX 4070 sleep: hardware discovery reads registry/CPUID strings only.
  No CUDA, no NVAPI, no DXGI adapter polling, no periodic GPU polling.
- MCP/Windows ML: discovery only (On-device Agent Registry paths, EP DLL
  presence). No inference is claimed without a verified model+driver;
  CPU fallback is the default routing decision.

## Slices

1. Services (SCM EnumServicesStatusExW / QueryServiceConfigW, deps).
2. Processes + EcoQoS.
3. Battery (GetSystemPowerStatus, discharge W from sampled deltas) + profiles.
4. Hardware (registry-only, G-Helper coexistence note: read-only, no fan/GPU-mode writes).
5. Capabilities: Windows build, MCP registry, WinML EPs (VitisAI/MIGraphX/DML/CPU).
6. AI tools (read-only) + validated, approval-gated suggestions; UI sections;
   History & Rollback.

## Testing

Rust unit tests for policy/protection/profiles/routing; TS tests for
validation/profile logic; `bun run release:check` gate. Hardware behaviour
that needs the physical G16 is documented as unverified in the PR.
